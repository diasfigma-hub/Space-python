# Материалы к защите проекта

Игра: **«Космические войны лололошек»**
Файл запуска: `main.py`, язык Python, библиотека Pygame.

---

## 1. Что представляет собой игра

Это двухмерная космическая аркада. Внизу экрана находится корабль игрока, сверху падают
астероиды. Игрок двигает корабль, стреляет по камням и старается не столкнуться с ними.

Правила короткие:

- двигать корабль — клавиши `W`, `A`, `S`, `D`;
- пробел — ускорение, корабль летит почти в два раза быстрее;
- левая кнопка мыши — выстрел;
- у астероида три единицы прочности: три попадания, и он разрушается;
- после первого попадания камень трескается, после второго становится обломками,
  после третьего исчезает и приносит 10 очков;
- у игрока три жизни, столкновение с камнем отнимает одну;
- когда жизни закончились — экран поражения с итоговым счётом.

Режим бесконечный: уровней и волн нет, астероиды появляются постоянно, а сложность
не растёт — темп всегда одинаковый. Победного экрана нет, игра идёт до последней жизни.

## 2. Как запустить

```bat
pip install -r requirements.txt
python main.py
```

## 3. Как устроен игровой цикл

Вся игра — это один цикл `while running` в функции `main()`. Один проход цикла — один кадр.
За кадр программа успевает:

1. узнать, что нажал игрок (`pg.event.get()` и `pg.key.get_pressed()`);
2. посмотреть, какой сейчас экран (`state`), и выбрать нужную ветку;
3. на игровом экране вызвать `update_game(dt)` — игра делает шаг вперёд;
4. вызвать функцию отрисовки (`draw_game()`, `draw_menu()`, `draw_pause()` или
   `draw_game_over()`);
5. показать готовый кадр на экране (`pg.display.flip()`).

Затем цикл повторяется. 60 раз в секунду — значит, всё это происходит 60 раз в секунду,
и глаз видит плавное движение.

Важная переменная — `dt`. Это время между кадрами в секундах (примерно 0,016 с).
Все скорости умножаются на `dt`:

```python
player_y -= speed * dt
```

Поэтому на быстром компьютере игра не ускоряется, а на медленном не замедляется:
за секунду корабль всегда пролетает одинаковое расстояние.

## 6. Как хранятся данные

Классов в проекте нет, поэтому всё состояние — это обычные переменные модуля:

| Переменная | Что хранит |
|---|---|
| `state` | название экрана: `"menu"`, `"playing"`, `"paused"` или `"over"` |
| `player_x`, `player_y` | где находится корабль |
| `lives` | сколько жизней осталось |
| `score` | сколько очков набрано |
| `asteroids` | список всех камней на экране |
| `bullets` | список всех пуль |
| `spawn_timer` | сколько секунд осталось до появления нового камня |
| `shoot_timer` | сколько секунд осталось до следующего выстрела |

Каждый астероид — это список из четырёх чисел:

```python
[500, -80, 120, 3]   # x, y, скорость, прочность
```

Читается так: камень в точке (500, −80) летит со скоростью 120 пикселей в секунду,
и у него осталось 3 единицы прочности. Список выбран специально: он короче словаря
и понятен новичку.

Пуля — список из двух чисел: `[x, y]`.

Кнопки экранов — это `pg.Rect` (`play_rect`, `resume_rect`, `again_rect` и другие):
по ним легко проверить, попал ли клик в кнопку.

## 7. Как обрабатывается управление

Есть два разных способа узнать про ввод, и в игре используются оба:

- **События** (`pg.event.get()`) — одноразовые нажатия: закрыть окно, нажать `Esc`,
  кликнуть по кнопке. Событие приходит один раз.
- **Состояние клавиш** (`pg.key.get_pressed()`) — какие клавиши **сейчас** зажаты.
  Это нужно для движения: пока держим `W`, корабль летит вверх каждый кадр.

```python
keys = pg.key.get_pressed()
speed = BOOST_SPEED if keys[pg.K_SPACE] else PLAYER_SPEED
if keys[pg.K_w]:
    player_y -= speed * dt
```

Стрельба проверяется так же, только для мыши: `pg.mouse.get_pressed()[0]`.
Чтобы пули не летели сплошной стеной, после выстрела ставится пауза `SHOOT_DELAY = 0.16` с.

## 8. Как отображаются картинки

При запуске картинки один раз загружаются с диска и масштабируются:

```python
image = pg.image.load(path).convert_alpha()
return pg.transform.scale(image, size)
```

Дальше каждый кадр они просто ставятся на экран в нужную точку через `blit`.
Корабль рисуется по центру своих координат:

```python
screen.blit(ship, ship.get_rect(center=(player_x, player_y)))
```

Путь к файлу собирается от папки с программой (`BASE_DIR`), а не прописан жёстко.
Иначе игра работала бы только на одном компьютере.

Картинка корабля выбирается по нажатым клавишам: пробел — кадр ускорения, любая из WASD —
кадр полёта, иначе — кадр покоя.

## 9. Как реализованы столкновения

Каждый объект считается кругом: у пули радиус 4, у астероида 28, у корабля 26.
Два круга пересекаются, если расстояние между центрами меньше суммы радиусов.
Считать расстояние с корнем медленнее, поэтому сравниваются квадраты:

```python
def hit(x1, y1, r1, x2, y2, r2):
    dx = x1 - x2
    dy = y1 - y2
    return dx * dx + dy * dy < (r1 + r2) ** 2
```

Так проверяются попадания пуль и столкновения с кораблём. Круги выбраны потому,
что астероиды круглые, а такой способ работает быстро и просто объясняется.

## 10. Прочность астероида и очки

Четвёртое число в списке астероида — прочность. Каждое попадание уменьшает её на единицу:

```python
asteroid[3] -= 1
if asteroid[3] <= 0:
    asteroids.remove(asteroid)
    score += 10
```

Пока прочность 2 или 1, астероид остаётся на экране и просто меняет картинку.
В отрисовке номер картинки считается так:

```python
image = asteroid_images[3 - asteroid[3]]
```

При прочности 3 берётся картинка номер 0 (целый камень), при 2 — номер 1 (треснутый),
при 1 — номер 2 (обломки). Очки дают только за третье попадание, за трещины — нет.

## 11. Жизни и поражение

```python
for asteroid in asteroids[:]:
    if hit(player_x, player_y, 26, asteroid[0], asteroid[1], 28):
        asteroids.remove(asteroid)
        lives -= 1
```

Столкновение убирает камень и отнимает одну жизнь. Неуязвимости и мигания нет:
каждое столкновение стоит ровно одну жизнь, но и камень после удара исчезает,
поэтому повторно жизнь не снимет.

Когда жизни кончились, меняется экран:

```python
if lives <= 0:
    lives = 0
    state = "over"
```

Дальше главный цикл видит `state == "over"` и рисует экран поражения с кнопками
«Играть снова» и «В меню».

## 12. Меню и пауза

Экраны переключаются одной переменной `state`:

| `state` | Что видит игрок | Как выйти |
|---|---|---|
| `"menu"` | название и кнопка «Играть» | клик по кнопке или `Enter`, `Esc` — выход из игры |
| `"playing"` | игра | `Esc` — пауза |
| `"paused"` | затемнение, «Продолжить» и «В меню» | `Esc` — продолжить, `Q` — в меню |
| `"over"` | «ИГРА ОКОНЧЕНА», очки, две кнопки | `R` или `Enter` — заново, `Esc` — в меню |

Никаких отдельных классов экранов нет: просто `if state == "..."` и вызов нужной
функции отрисовки.

## 13. Какие библиотеки используются и зачем

- **Pygame** — единственная внешняя библиотека. Даёт окно, рисование картинок и фигур,
  шрифты, обработку клавиатуры и мыши, ограничение частоты кадров.
- **os, random** — встроенные модули Python: пути к файлам и случайные числа для камней
  и звёзд.

Больше ничего не подключалось: сервер, база данных и сложные движки для одиночной
аркады не нужны. Модуль `math` тоже не нужен — его убрали вместе с частицами и вращением.

## 14. Трудности и как они решены

| Трудность | Решение |
|---|---|
| Игра не запускалась из другой папки — не находились картинки | путь собирается от `BASE_DIR` через `os.path.join` |
| Окно 1920×1080 не помещалось на ноутбуке | окно 1280×720 |
| Картинки растягивались неровно | они масштабируются под размер окна одной функцией `load_image()` |
| Игра на разных компьютерах шла с разной скоростью | все скорости умножаются на `dt` |
| Код был перегружен эффектами | убраны частицы, вращение камней, второй набор корабля и растущая сложность |
| Астероид исчезал от одного попадания | у камня три единицы прочности и три картинки состояния |

# Вероятные вопросы преподавателя и ответы

**1. Что делает твоя игра?**
Космическая аркада: корабль внизу, астероиды падают сверху. Нужно стрелять по камням,
уворачиваться и продержаться как можно дольше. Есть очки, три жизни, пауза и экран поражения.

**2. Почему выбрал Pygame, а не Unity?**
Pygame — библиотека для Python, ставится одной командой и не требует мощного компьютера.
Весь код игры виден и понятен, а Unity — большой движок с редактором, для такой
небольшой игры он избыточен.

**3. Что такое игровой цикл?**
Это главный `while`, который повторяется 60 раз в секунду. Каждый проход: прочитать ввод,
обновить состояние игры, нарисовать кадр, показать его. Без цикла игра показала бы
одну картинку и остановилась.

**4. Что такое dt и зачем он?**
Это время между кадрами в секундах. Скорости умножаются на `dt`, поэтому движение
не зависит от скорости компьютера: за секунду корабль всегда пролетает одно расстояние.

**5. Почему 60 кадров в секунду?**
Это стандарт: плавно для глаза и не нагружает компьютер. Больше кадров почти не заметно,
а нагрузка выше.

**6. Чем отличаются `pg.event.get()` и `pg.key.get_pressed()`?**
`event.get()` даёт одноразовые события: нажал `Esc` — пришло одно событие.
`key.get_pressed()` показывает, какие клавиши зажаты прямо сейчас. Движение делается
вторым способом, а пауза и клики по кнопкам — первым.

**7. Как реализованы столкновения?**
Каждый объект — круг со своим радиусом. Если расстояние между центрами меньше суммы
радиусов, значит, они столкнулись. Сравниваю квадраты расстояний, чтобы не считать корень.

**8. Почему не использовал классы?**
Игра небольшая: состояние — это набор переменных, поведение — функции. С классами
кода стало бы больше, а понятнее он бы не стал. Мне важно, чтобы проект можно было
объяснить построчно.

**9. Как хранится информация об астероиде?**
Это список из четырёх чисел: `x`, `y`, скорость и прочность. Все камни лежат
в списке `asteroids`. Список выбран вместо словаря, потому что он короче и проще читается.

**10. Что происходит при столкновении астероида с кораблём?**
Камень удаляется, у игрока становится на одну жизнь меньше. Если жизней не осталось,
игра переключается на экран поражения.

**11. Как работают три попадания по астероиду?**
У камня есть прочность 3. Каждое попадание пули уменьшает её на единицу. При прочности 2
показывается картинка треснутого камня, при 1 — обломков. Когда прочность стала нулём,
камень удаляется из списка и начисляется 10 очков.

**12. Как начисляются очки?**
По 10 за каждый уничтоженный астероид — только за третье попадание. Максимума нет.

**13. Зачем нужна задержка стрельбы?**
`SHOOT_DELAY = 0.16` секунды. Без неё за один кадр появлялось бы несколько пуль,
и игрок просто заливал бы экран пулями. С задержкой получается нормальный темп стрельбы.

**14. Как работает ускорение?**
Пока зажат пробел, вместо скорости 340 берётся 560 пикселей в секунду:

```python
speed = BOOST_SPEED if keys[pg.K_SPACE] else PLAYER_SPEED
```

Ещё меняется картинка корабля, чтобы игрок видел, что ускорение включено.

**15. Как переключаются экраны?**
Переменная `state` хранит название экрана: `menu`, `playing`, `paused`, `over`.
Главный цикл смотрит на неё и вызывает нужные функции обработки и отрисовки.

**16. Что происходит, когда жизни закончились?**
Игра ставит `state = "over"` и показывает экран «ИГРА ОКОНЧЕНА» с итоговым счётом,
кнопками «Играть снова» и «В меню». Рекорд не сохраняется — проект остаётся простым,
без файлов на диске.

**17. Как загружаются картинки и почему путь не ломается?**
При запуске они один раз читаются с диска, масштабируются и дальше просто копируются
на экран. Путь строится от папки, где лежит `main.py`, через `os.path.join`. Поэтому игру
можно запускать из любого места.

**18. Почему сложность не растёт?**
Так проще и честнее: правила одинаковые от первого камня до последнего. Раньше сложность
считалась от очков, но это добавляло в код лишние функции и формулы, а игра становилась
понятнее не намного.

**19. Что было в исходной версии, а что добавил ты?**
В исходной версии были корабль, падающие астероиды, пули и звёздный фон, но не было
столкновений, очков, жизней и экранов. Я добавил игровую логику, столкновения, прочность
камня, очки, меню, паузу и экран поражения. Потом упростил код: убрал частицы, вращение
и лишние механики, чтобы игра стала понятнее.

**20. Что можно улучшить дальше?**
Добавить вражеские корабли, бонусы (например, тройной выстрел), звук и сохранение
лучшего счёта между запусками. Основа готова: списки объектов и функция `update_game()`
легко расширяются.

> Состояние игры хранится в обычных переменных: положение корабля, жизни, очки, таймеры.
> Астероиды лежат в списке, и каждый — это список из четырёх чисел: координаты, скорость
> и прочность. Пули — просто пары координат. Классы я не использовал: для такой игры
> хватает переменных и функций, а объяснить такой код проще.
>
> Столкновения считаются по кругам: если расстояние между центрами меньше суммы радиусов,
> объекты столкнулись. Это быстро и понятно, потому что камни круглые.
>
> Попадание устроено так: у камня есть прочность, каждое попадание уменьшает её
> на единицу. Пока прочность два или один, камень просто меняет картинку. Когда она стала
> нулём, камень удаляется из списка и добавляется десять очков.
>
> Экраны переключаются переменной `state` — меню, игра, пауза, поражение. Оформление
> сделано на исходных картинках: кадры корабля, три состояния астероида и пуля.
> Фон — тёмный космос и звёзды, всё нарисовано кодом.
>
> Из трудностей: игра сначала не находила картинки, если её запускали из другой папки, —
> я стал собирать путь от расположения файла. Окно было слишком большим для ноутбука —
> уменьшил до 1280 на 720. А ещё я упростил игру: убрал частицы, вращение камней
> и растущую сложность, потому что они не влияли на правила, а код усложняли.
>
> Игру я проверил: три попадания по камню, начисление очков, потерю жизней, поражение,
> ускорение, все кнопки меню и паузы. Скриншоты в документации сделаны из настоящего кода
> отрисовки.
>
> В дальнейшем игру можно развить: добавить вражеские корабли, бонусы и звук. Спасибо
> за внимание, готов ответить на вопросы.

## Быстрая шпаргалка перед защитой

- Запуск: `python main.py`, зависимости: `pip install -r requirements.txt`.
- Размер окна: 1280×720, 60 кадров в секунду, файл `main.py` — 388 строк, 13 функций.
- Управление: WASD — движение, пробел — ускорение (340 → 560), ЛКМ — выстрел.
- Астероид: прочность 3, три картинки, 10 очков за третье попадание.
- Жизни: 3, выводятся текстом «Жизни: N».
- Сложность постоянная: камень раз в 0,9 с, скорость 90–140 пикселей в секунду.
- Столкновения: расстояние между центрами меньше суммы радиусов (4, 28, 26).
- Экраны: `menu`, `playing`, `paused`, `over`.
- Рекорда нет, классы не используются.
